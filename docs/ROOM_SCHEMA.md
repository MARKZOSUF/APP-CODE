# Room schema

Database `insangram.db`, version 2, 31 entities across 8 DAOs. Schemas are
exported to `app/schemas/` via the KSP `room.schemaLocation` argument so
migrations can be tested.

**No password and no authentication token is ever stored here.**

---

## Mapping to the requested entity list

The brief names 21 entities. This schema implements all of them, sometimes
under a clearer name, plus ten more that the feature set turned out to need.

| Requested | Implemented as |
| --- | --- |
| CachedUser, CachedPost, CachedPostMedia, CachedStory, CachedReel, CachedComment, CachedConversation, CachedMessage, CachedNotification | same names |
| FeedRemoteKey, ReelRemoteKey, LocalDraft, PendingUpload, PendingAction, MediaCacheEntry, SyncMetadata | same names |
| SearchHistory | `SearchHistoryEntity` |
| UserPreferences | DataStore (`InsangramPreferences`) — typed preferences do not belong in a relational table |
| DemoLike | `LikeEntity` — used by both flavors, not demo-specific |
| DemoFollow | `FollowEdge` — likewise |
| DemoSavedPost | `SavedPostEntity` — likewise |

Additional entities: `CachedNote`, `BlockEdge`, `SavedCollectionEntity`,
`StoryViewEntity`, `HashtagEntity`, `AnalyticsSnapshot`, `DemoAccount`,
`ContentReportEntity`, `NegativeSignalEntity`, `InterestSignalEntity`,
`WatchTimeEntity`.

## Content tables

**CachedUser** — `userId` PK; username, normalizedUsername, fullName, bio,
website, pronouns, photoUrl, isPrivate, counts, createdAt, lastActiveAt,
`cachedAt`. Indexed on `normalizedUsername`.

**CachedPost** — `postId` PK; authorId, caption, locationName, hashtags,
taggedUserIds, mentionedUsernames, counts, commentsEnabled, hideLikeCount,
isArchived, deletedAt, createdAt, editedAt, feedScore, cachedAt. Indexed on
`authorId`, `createdAt`, `feedScore`, `deletedAt`.

**CachedPostMedia** — autogenerated PK, `postId` FK with cascade delete,
position, mediaUrl, thumbnailUrl, mediaType, dimensions, durationMs, altText,
`localUri`, `mediaHash`. `localUri` is how demo mode renders bundled assets and
how an upload shows its own bytes before the remote URL exists.

**CachedStory**, **CachedReel**, **CachedComment**, **CachedConversation**,
**CachedMessage**, **CachedNotification**, **CachedNote** follow the same
pattern: the remote id as PK, denormalized author id, and a `cachedAt` stamp
driving expiry.

---

## Graph tables

**FollowEdge** — composite PK `(followerId, followeeId)`. This is what makes
duplicate follows and duplicate requests impossible locally, mirroring the
Firestore document-id convention. Carries `state`, `isCloseFriend`,
`mutedPosts`, `mutedStories`.

**BlockEdge** — composite PK `(blockerId, blockedId)` with a `restrictedOnly`
flag, so block and restrict share one table.

**LikeEntity** — composite PK `(userId, contentId, contentType)`, covering post,
reel and comment likes in one place.

**SavedPostEntity** — composite PK `(userId, postId)` with a nullable
`collectionId`. **SavedCollectionEntity** holds the collection itself.

**StoryViewEntity** — composite PK `(storyId, viewerId)`, carries the reaction.

## Paging and sync tables

**FeedRemoteKey** / **ReelRemoteKey** — Paging 3 `RemoteMediator` cursors,
storing `prevCursor`, `nextCursor`, `position` and `fetchedAt`.

**LocalDraft** — a survivable post or story draft: caption, media URIs, alt
texts, tagged users, applied filter and adjustment values.

**PendingUpload** — `state` in `QUEUED | RUNNING | SUCCEEDED | FAILED |
CANCELLED`, with `progressPercent`, `attemptCount`, `lastError`, `mediaHash`
and `idempotencyKey`. `UploadWorker` drains it and survives process death.

**PendingAction** — queued mutations (`LIKE`, `FOLLOW`, `COMMENT`,
`SEND_MESSAGE`, …) with a payload and an `idempotencyKey` so a retry cannot
double-apply. Drained by `PendingActionWorker` under a network constraint.

**MediaCacheEntry** — LRU accounting for downloaded media, with
`lastAccessedAt` and `sizeBytes`, trimmed against a byte budget.

**SyncMetadata** — per-collection `lastSyncedAt` and cursor.

---

## Signal tables

**NegativeSignalEntity** — `HIDDEN | NOT_INTERESTED | REPORTED` per content id.
**InterestSignalEntity** — `hashtag:<tag>` and `creator:<userId>` weights,
clamped to `0.0..25.0`, nudged +1.0 on a like and −1.5 on a negative signal.
**WatchTimeEntity** — accumulated milliseconds and completion count per reel.

These three feed `FeedRankingUseCase` and are the reason ranking works fully
offline.

---

## Demo-only

**DemoAccount** — `userId` PK, email, `passwordHash`, `passwordSalt`,
`iterations`, `emailVerified`. PBKDF2-SHA256 only; no plaintext ever.

---

## Type converters

`InsangramConverters` maps `List<String>`, `Map<String, String>` and enum values
to JSON strings via kotlinx.serialization, keeping the schema readable.

---

## Migrations

`InsangramMigrations.ALL` currently holds `MIGRATION_1_2`. The rule for any
schema change: bump `InsangramDatabase.VERSION`, add a migration, add a test
against the exported JSON schema. `fallbackToDestructiveMigration` is **not**
enabled, because silently deleting a user's cache and drafts is not acceptable.

---

## Cache expiry

`cachedAt` drives eviction. `MaintenanceWorker` runs periodically to evict rows
older than the TTL while preserving the signed-in user's own content, purge
soft-deleted posts past retention, archive expired stories and trim the media
cache to its byte budget.
